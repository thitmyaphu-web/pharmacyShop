Medi Shop (Flutter Pharmacy App) — Architecture & Dev Documentation

Technical Design, BLoC State Pipeline, UI System & Handover Guide for the Medi Shop Flutter Mobile Application.

1. Executive Summary & Core App Pipeline

UI Widgets (Screens) → PharmacyEvent → PharmacyBloc → MedicineRepository → MedicineService → PharmacyState

Medi Shop is a lightweight, clean-card-style online pharmacy application built with Flutter (Dart) and BLoC (flutter_bloc) state management. It is structured with a layered architecture so that local Dart sample data can be swapped for a real REST API or Firebase backend without changing any UI code.

  1. Catalog & Discovery: Displays medicines in clean Material 3 cards with real-time keyword search and category filtering (All, Fever & Pain, Vitamins, Antibiotics, Allergy).
  2. Medicine Details & Rx Safety: Dedicated detail view showing unit packaging, live stock count, usage description, and a highlighted prescription (Rx) warning banner for controlled medicines.
  3. Cart & Stock-Safe Checkout: Interactive shopping cart with quantity increment/decrement controls capped by available stock, automatic subtotal/total calculation, and instant stock deduction upon checkout.
  4. Dynamic Theming: One-tap Light Mode and Dark Mode switcher managed reactively through PharmacyBloc and Material 3 ColorScheme.

2. BLoC Architecture & Sequence Alignment

All business logic is decoupled from Flutter widgets. User interactions dispatch typed events to PharmacyBloc, which communicates with MedicineRepository and emits immutable PharmacyState snapshots: 

[User Action] ──► (Flutter UI) ──► [PharmacyEvent] ──► (PharmacyBloc) ──► [MedicineRepository]
                                                                                  │
[UI Rebuild]  ◄── (BlocBuilder) ◄── [PharmacyState] ◄─────── (MedicineService) ◄──┘

Mapping Matrix: BLoC Events vs. UI States

Event Class UI Trigger State Transition & Side Effects
LoadMedicines App startup (main.dart) Emits PharmacyStatus.loading → fetches catalog → emits loaded or error.
SearchMedicines(query) Search TextField.onChanged Filters allMedicines by name/category combined with active category chip.
SelectCategory(category) ChoiceChip.onSelected Updates selectedCategory and recalculates filteredMedicines.
AddToCart(medicine) Card / Detail Add button Adds item or increments quantity if quantity < medicine.stock.
UpdateCartQuantity Cart + / - icon buttons Updates item count within 1..stock; removes item if quantity reaches 0.
CheckoutOrder Cart Place Order button Deducts purchased quantities from stock, clears cart, sets orderSuccessMessage.
ToggleTheme AppBar Light/Dark icon button Flips isDarkMode boolean, switching MaterialApp.themeMode immediately.

4. Project Folder Structure & Module Breakdown

The codebase follows a clean feature-layered Flutter folder structure: 

lib/
├── constants/
│   └── app_constants.dart         # Brand colors, categories, Light & Dark ThemeData
├── models/
│   ├── medicine.dart              # Medicine entity (fromJson, toJson, copyWith)
│   └── cart_item.dart             # CartItem entity with subtotal calculation
├── services/
│   └── medicine_service.dart      # Local Dart medicine data provider
├── repositories/
│   └── medicine_repository.dart   # Repository abstraction for BLoC
├── logic/
│   ├── pharmacy_event.dart        # All user & system BLoC events
│   ├── pharmacy_state.dart        # Immutable state, cart totals, theme flag
│   └── pharmacy_bloc.dart         # Event handlers, filtering & checkout logic
├── ui/
│   ├── widgets/
│   │   └── medicine_card.dart     # Reusable clean card component with Rx badge
│   └── screens/
│       ├── home_screen.dart       # Search, category chips, theme toggle, catalog
│       ├── medicine_detail_screen.dart # Full medicine info & Rx warning banner
│       └── cart_screen.dart       # Quantity controls, total bar, checkout CTA
└── main.dart                      # App entry point, BlocProvider & ThemeMode

Dependencies (pubspec.yaml)

  • flutter (SDK) — Core UI framework with Material 3 enabled (useMaterial3: true).
  • flutter_bloc: ^8.1.6 — Predictable state management (BlocProvider, BlocBuilder, BlocListener).

6. Data Models & Business Rules

Medicine Schema (lib/models/medicine.dart)

Field Type Description / Validation Rule
id String Unique identifier (e.g., med_1).
name String Display name & dosage (e.g., Paracetamol 500mg).
category String Matches one of AppConstants.categories.
unit String Packaging description (e.g., 10 Tablets / Strip).
price int Unit price in Myanmar Kyat (Ks).
stock int Available inventory; prevents adding beyond stock limit.
requiresPrescription bool If true, displays Rx badge and medical warning banner.
description String Usage summary displayed on MedicineDetailScreen.

7. Assignment Handover & QA Verification Checklist

  • Clean Architecture Separation: Constants, Models, Services, Repositories, BLoC Logic, and UI Screens are strictly separated.
  • Dart-Native Data Layer: MedicineService provides strongly typed Medicine objects without requiring external JSON asset configuration.
  • Real-Time Search & Filtering: Search input and horizontal category chips work together seamlessly.
  • Stock-Safe Cart Logic: Add/increment buttons automatically disable when cart quantity reaches available stock.
  • Light & Dark Theme Toggle: AppBar icon switches between ThemeMode.light and ThemeMode.dark across all screens.
  • Order Confirmation Flow: Checkout deducts stock, empties the cart, navigates back, and triggers a confirmation SnackBar.
